# Epics: the map and the menu

An epic is a piece of work made of several distinct parts, called topics. Confirming an epic opens a conversation across the whole of it rather than ending one, and when you say the ground is covered Claude draws out the topics, each with a brief carrying what concerns it and the questions still open. The result is the epic's map, which you approve before any topic starts.

The epic's menu is how you live with it. Its heading is the phase the epic is in, with a tally beneath: how many topics, how many decided, in progress, not started, cancelled or postponed. Then come the rows: what waits on you first, then a row for each topic you can pick up, the recommended one first. Decided topics and those set aside are listed with no key.

```
   Continue "Billing"    in progress, pick up where it was
   Start "Usage Limits"  not started yet
   mail waiting          another topic sent it a message
   in session            another session is working it now
```

A topic in session elsewhere stays on the menu, struck through, and entering it asks first. Mail waiting means another topic sent this one a message: something it turned up that this topic owns, raised here as a question when the topic is next opened. A decided topic comes back among what waits on you when a decision it relies on has changed.

Changing the map is the discovery row's job: a new topic, cancelling one, postponing one to the roadmap, pulling one forward, bringing one back, or reopening a decided one. Once every topic is decided, cancelled or postponed, the menu offers the specification; during the build it shows which phase the build is on, then the review. From the specification's first writing the map is closed, and a decision that has to change is settled in the phase the epic is in.
