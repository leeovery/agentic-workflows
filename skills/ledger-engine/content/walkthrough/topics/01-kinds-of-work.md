# The kinds of work

Not every piece of work deserves the same process. A tweak to a settled feature and a months-long initiative both benefit from some structure, but forcing the tweak through weeks of discussion would be absurd and letting the initiative skip straight to code would be reckless. So there are four kinds of work, each with a route sized to fit, and the kind is settled for you at the start from how you describe what you want.

```
   epic        several distinct things wearing one name;
               each becomes a topic, talked through on its own
   feature     one coherent thing to build, start to finish
   bugfix      something that used to work and now doesn't;
               an investigation finds the cause first
   quick-fix   work of any size that takes no deciding
               beyond a quick call; built and closed in one
               session
```

You never have to choose. Press `s` on the start menu, or just ask Claude for the change, describe the work, and discovery works out the kind in conversation, telling you its read and asking whether it's right before anything is created.

A piece of work of any kind is a work unit. Inside an epic the separate parts are called topics; for every other kind the topic is simply the work itself and the word never comes up.

Getting the kind wrong at the start costs little. A feature that grows into several things can pivot into an epic, and one that belongs inside a larger effort can be absorbed into one, both from manage on the start menu, before its specification is written. A quick-fix that turns out to need a real decision moves to a feature or a bugfix within its own session. The card *Reshaping work* covers these.
